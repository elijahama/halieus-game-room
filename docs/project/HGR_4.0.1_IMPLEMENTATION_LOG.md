# HGR 4.0.1 Implementation Log

## Scope

HGR 4.0.1 is a presentation and mobile-layout patch built on the 4.0.0 platform baseline.

The patch does **not** change Mega Board ranked rating calculations, placement rules, award scoring, room authority, or server game-state rules. It changes how existing authoritative results are presented to players.

## Changes implemented

### 1. Mega Board ranked-results hierarchy

File: `client/src/games/mega-board/components/WinnerScreen.tsx`

The old ranked summary used one dense four-column row per player:

- placement/name;
- rating before → after;
- rating delta;
- one long sentence containing placement, performance and award bonuses.

4.0.1 replaces that presentation with structured ranked-result cards.

Each card now shows:

- finishing position marker;
- player name;
- rating before → rating after;
- total rating delta;
- separate Placement, Performance and Awards bonus blocks;
- award names as individual chips.

The underlying values are still read directly from `gameState.rankedResults`. No client-side rating recalculation was introduced.

### 2. Mobile final-results cards

Files:

- `client/src/games/mega-board/components/WinnerScreen.tsx`
- `client/src/index.css`

Desktop keeps the existing wide final-results table.

On phones, the table converts to labelled player cards. Metric labels are provided through `data-label` attributes so the same result markup can serve both desktop and mobile without duplicating game data.

Mobile cards expose:

- Revenue
- Expenses
- Profit / loss
- Properties
- Rent collected
- Builds
- Trades

### 3. Results navigation and responsive hierarchy

File: `client/src/index.css`

The Results / Stats / Awards navigation is explicitly three columns, matching the three rendered tabs.

Phone layouts now:

- reduce result-card padding;
- keep the winner hero readable;
- use a sticky results-tab rail;
- collapse ranked player rows into a single-column card flow;
- stack footer actions;
- avoid horizontal panning for the main standings;
- allow the graph itself to scroll horizontally when its minimum readable width exceeds the phone viewport.

### 4. Mobile foundation carried forward

The earlier 4.0.0 mobile recovery pass remains in place and is part of the 4.0.1 patch baseline:

- four-column Home / Games / Join / Players mobile navigation;
- Ludo turn controls in normal document flow;
- compact mobile game metadata rail;
- bounded embedded room chat;
- mobile game-menu bottom-sheet behaviour;
- compact theme/settings controls;
- safe-area handling.

### 5. Version progression

HGR now uses normal semantic patch progression.

4.0.1 updates:

- `VERSION`
- root `package.json`
- client/server/shared/desktop package versions
- `package-lock.json`
- `shared/version.ts`
- PWA cache identity
- intro asset cache-buster
- README milestone

`RELEASE.json` and `shared/release.ts` are intentionally **not hand-edited**. They must be regenerated by `npm run prepare:release` after the complete 4.0.1 source is pulled locally and validated.

## Code-comment requirement

New non-trivial 4.0.1 implementation sections include source comments explaining:

- presentation-only ranked-result logic;
- mobile metric labelling;
- CSS override intent;
- mobile card-layout assumptions;
- regression-test scope.

The project standard remains: important functions, algorithms, rule boundaries, recovery behaviour and non-obvious UI layout logic should explain their intent in-source rather than relying only on external documentation.

## Regression coverage

New test:

`tests/regression-4.0.1.mjs`

It checks:

- all canonical package versions are 4.0.1;
- 4.0.1 follows 4.0.0 in the regression chain;
- ranked-result card structure exists;
- ranked bonus breakdown and award strip exist;
- mobile result labels exist;
- phone standings do not depend on the desktop table heading;
- the Results / Stats / Awards rail uses three columns;
- the PWA and intro cache identities are 4.0.1;
- README reports the 4.0.1 milestone.

The historical 4.0.0 regression was adjusted so later 4.0.x patches can preserve the 4.0.0 behavioural contract without falsely requiring the current patch number to remain 4.0.0.

## Validation status

Source changes and regression guards are committed to GitHub.

Before production packaging:

1. pull `main` into the canonical HGR laptop folder;
2. run `npm run typecheck`;
3. run `npm run build`;
4. run `npm run test:regression`;
5. perform phone/tablet browser checks;
6. run `npm run prepare:release` to generate the final 4.0.1 release fingerprint;
7. package/deploy through the normal Oracle candidate flow.

The release fingerprint is not considered final until those local validation steps complete.
