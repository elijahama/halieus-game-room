# Halieus Game Room 3.5.26 — Release Integrity & Stability

## Why this release exists

3.5.24/3.5.25 exposed a release-integrity failure: a visible version label was not sufficient proof that the promised frontend source was actually the code being tested. Launcher and deployment responsibilities had also become coupled.

3.5.26 makes the release pipeline verifiable before additional feature work continues.

## Release/deployment fixes

- Start and Restart cannot invoke Update, Oracle deployment, or remote shell commands.
- Routine Update no longer installs operating-system packages or reconfigures nginx/Certbot.
- First-time Oracle provisioning is isolated in `provision-oracle.sh`.
- `RELEASE.json` carries a SHA-256 source fingerprint generated by `scripts/release-integrity.mjs`.
- Oracle recomputes that fingerprint before it builds the candidate.
- Server `/health` exposes `releaseFingerprint` alongside `version`.
- Activation succeeds only if Oracle reports the exact package version and fingerprint.
- A wrong/missing fingerprint triggers automatic application rollback.
- Public HTTPS health is diagnostic after Oracle exact verification; it no longer causes the false “update failed” result seen in prior builds.

## UI stabilization included

- Bypass the oversized theatrical pre-login intro.
- Persistent System / Light / Dark theme selection.
- Full Screen + Theme grouped in the platform/account surfaces.
- Desktop Home/Game Room sidebar constrained to `100dvh` so its lower controls do not drift below the viewport.
- Existing Home active-game Join/Spectate discovery retained.
- Existing Players filters/stats/live-room actions retained.
- Connect Four player-marker sizing only.
- Blackjack desktop seat containment only.
- No new global CSS zoom/scale hack.

## Protected code

Poker and Ludo approved gameplay files are guarded by release regression hashes. Their client screens and server handlers are unchanged in this pass.

## Not part of 3.5.26

This build does not claim the planned new game modules, the full Owner information-architecture rebuild, or the complete native friend-invite system. Those remain follow-on work after this release pipeline is proven on the live site.
